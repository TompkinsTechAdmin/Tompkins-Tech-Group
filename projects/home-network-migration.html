Building and Troubleshooting My Home Network.

A hands-on migration involving OpenWrt routing, centralized DHCP, a managed switch, and a stubborn 100 Mbps connection that needed some detective work.

Project overview

My home lab supports virtualization, Linux services, networking practice, and everyday household devices. I wanted to evolve the network without disrupting the services everyone depends on. The approach was to retain the existing flat LAN initially, introduce a dedicated OpenWrt router/firewall, and separate DHCP service responsibilities while keeping the wireless mesh available.

What I was working with

  • A Spectrum Internet connection and an existing TP-Link Deco wireless mesh.
  • A managed Netgear ProSafe switch providing wired connectivity.
  • A Cisco Meraki appliance running OpenWrt as the replacement router and firewall.
  • A Linux virtual machine running ISC Kea for DHCPv4.
  • Proxmox hosts and other self-hosted services that needed stable addressing.

Migration approach

Rather than redesigning VLANs and routing simultaneously, I kept the network on one subnet during the initial migration. I tested the OpenWrt appliance separately, reviewed its firewall behavior, and confirmed its WAN interface could obtain an address dynamically. I then prepared Kea DHCP with a defined lease pool, router and DNS options, and a configuration test before enabling it for clients.

To avoid competing DHCP servers, I disabled DHCP service on the OpenWrt LAN interface while using Kea as the intended IPv4 DHCP server. I also verified that the server's own default route pointed to the network gateway.

Verifying DHCP

Validation mattered more than assuming a saved configuration meant success. On a Windows wireless client, I inspected the assigned address, subnet mask, default gateway, DHCP server, and DNS settings. The results showed the intended gateway, Kea DHCP server, and DNS resolvers. I then confirmed network reachability with ping tests.

Lesson learned: A DHCP service is not verified just because its configuration passes a syntax check. The real test is whether clients receive the correct options and can communicate.

The unexpected performance drop

After the network changes, Wi-Fi download speed fell to roughly 89–90 Mbps, despite a much faster Internet connection. The numbers suggested a physical Ethernet link negotiating at 100 Mbps rather than 1 Gbps, not necessarily a Wi-Fi radio problem.

I inspected the managed switch's port status and traced the Deco uplink to its connected port. The switch reported a 100 Mbps link. Manually forcing a gigabit speed was not a reliable fix, so I returned the port to automatic negotiation, reseated the cable, and moved the connection to another switch port.

Resolution and results

After reseating the cable and moving the Deco connection, the switch reported a 1,000 Mbps full-duplex link. A subsequent Wi-Fi speed test measured approximately 813.88 Mbps download and 40.11 Mbps upload, compared with about 89.67 Mbps download and 39.54 Mbps upload during the issue.

The evidence identified the 100 Mbps Ethernet uplink as the immediate bottleneck. The exact underlying cause, such as a marginal cable termination or port contact, was not conclusively isolated.

What this project taught me

  • Change one layer at a time when household availability matters.
  • Validate DHCP from a client, not just from the server.
  • Check physical link speed and duplex before tuning higher-layer services.
  • Use before-and-after measurements to confirm a troubleshooting hypothesis.
  • Keep configuration backups and a rollback path before infrastructure changes.

Next steps

With the initial routing and DHCP work functioning, future lab improvements can focus on documenting the topology, validating failover and recovery procedures, and eventually introducing network segmentation. Those changes will be separate, deliberate projects.

Documentation note: This public case study intentionally omits private IP addressing, credentials, configuration backups, and other sensitive implementation details.
